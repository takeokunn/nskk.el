# Phase 2 report

## Status

Complete. FR-004 (single ownership of the 8 shared buffer-local state
variables) is implemented, and its acceptance criterion — external modules
reach these variables only through `nskk-state.el` accessors — is met and
grep-verified tree-wide.

## Public API

`src/nskk-state.el` gained a getter/setter pair, generated by a new
`nskk-define-buffer-local-accessor` macro, for each of the 8 variables:

- `nskk-state-romaji-buffer` / `nskk-state-set-romaji-buffer`
- `nskk-state-conversion-start-marker` / `nskk-state-set-conversion-start-marker`
- `nskk-state-conversion-overlay` / `nskk-state-set-conversion-overlay`
- `nskk-state-pending-romaji-overlay` / `nskk-state-set-pending-romaji-overlay`
- `nskk-state-candidate-overlay` / `nskk-state-set-candidate-overlay`
- `nskk-state-dcomp-multiple-overlay` / `nskk-state-set-dcomp-multiple-overlay`
- `nskk-state-henkan-count` / `nskk-state-set-henkan-count`
- `nskk-state-registration-depth` / `nskk-state-set-registration-depth`

No `/k` CPS variants: each accessor targets one fixed, always-bound
`defvar-local`, so unlike `nskk-state-get`/`nskk-state-set` (which dispatch
on an arbitrary key and must distinguish "unknown key" from "known key,
nil value"), there is no ambiguity to resolve — a plain getter/setter pair
is the complete, correct API. All 8 variables remain buffer-local, per the
FR-004 constraint (not migrated into the Prolog global DB).

## Migration

Consumers moved off the private variables: `nskk-henkan.el` (all 8 vars,
~117 sites — the only file using all 8), `nskk-input.el` (5 vars, ~49
sites), `nskk-keymap.el` (4 vars, ~15 sites), `nskk-candidate-window.el` (2
vars, ~11 sites), `nskk.el`, `nskk-tutorial.el`, `nskk-inline.el`,
`nskk-custom.el` (docstring only), and 26 test files (~800+ sites total:
`nskk-henkan-test.el` alone had 458).

**Design problem and fix**: `nskk-ensure-overlay`, `nskk-delete-overlay`,
`nskk-ensure-marker` (existing macros in `nskk-state.el`, unchanged) take a
raw variable name and `setq` it in place. A naive "read via getter, call
macro on a local, write back via setter after" wrap is unsafe wherever the
macro's own operations can partially fail (e.g. `overlay-put` after
`make-overlay`) inside error/quit-sensitive code: the original `setq`
committed the new overlay to the shared variable immediately, before any
later risky step, but the wrap defers that commit until after the whole
macro call returns. `fr004-candwindow` found this as a real regression (an
integration test injecting a fault mid-`overlay-put` left a freshly created
overlay uncommitted to state, so rollback couldn't find it to delete —
leaked). Fixed by inlining the macro's logic at each such call site so the
accessor commit happens at exactly the point the original `setq` did (commit
before `overlay-put`/`delete-overlay`, not after). Applied at all of
`nskk-henkan.el`'s 14 macro call sites (several sit in
`nskk-rollback-conversion`, `nskk-cancel-conversion-to-reading`,
`nskk--clear-conversion-context`) and `nskk-candidate-window.el`'s 2. Plain,
non-transactional call sites elsewhere kept the simpler wrap-then-write-back
form.

Other notable per-file decisions:

- `nskk-keymap.el`'s `nskk--backspace-retract-pending` used a generic
  symbol-based snapshot/restore (`boundp`/`symbol-value`/`set`/`makunbound`)
  across an `atomic-change-group`; the two migrated vars (always-bound,
  never `makunbound`) were pulled out of that generic machinery and handled
  explicitly via the accessors, leaving the 4 unrelated AZIK vars untouched.
- `nskk-input-test.el` needed `cl-letf`-based dynamic rebinding for test
  isolation; since the underlying variables are no longer directly
  `let`-bindable, the test file registers file-local `gv-define-simple-setter`
  entries for the accessor pairs it uses, so `cl-letf` still works.
- `nskk-henkan-test.el`'s 458 sites were converted via a purpose-written
  sexp-aware transformer (not regex) preserving each `let`/`let*` block's
  exact save/restore semantics through `unwind-protect`.
- Several defensive `(boundp 'nskk--X)` guards across src/ and test/ were
  dropped, since the variables are now unconditionally bound via the
  accessor (matches `nskk-state.el`'s own documented invariant for these
  vars).
- `nskk--candidate-overlay-anchor` (an unrelated private helper in
  `nskk-candidate-window.el` whose name happened to textually contain
  `nskk--candidate-overlay`) was renamed to `nskk--candidate-anchor-position`
  so the completion grep check reflects genuine absence of the reference,
  not a naming coincidence.
